## Background

The original assignment was titled "Action-Game Combat-System Building and IP Character Design." The public result is a staged methodology study. Its completed first three chapters cover action PVP, resources, attack-defense transitions, balance, long-term operation, and IP gameplay translation. The planned character solution for Sword Snow Stride did not receive sufficient source verification or gameplay validation and is not published as a completed design.

## My Role

I independently selected cases, organized long-term play observations, analyzed combat rules, and summarized a framework covering base performance, in-match resources, attack-defense relationships, multi-player intervention, counterplay, and IP behavior translation. For the public edition, I retitled the work, removed drafts and the unfinished chapter, and reviewed the limits of each conclusion.

## Core Questions

- How does action depth emerge from information, action, cost, and feedback rather than the number of skills?
- How do basic attacks, movement, defense, counters, external abilities, and recoverable resources alter the next exchange?
- How can source behavior become gameplay that players can understand, practice, and counter rather than visual imitation alone?

## Process

Chapter one uses character-based action PVP to examine basic attacks, escape systems, combo protection, external abilities, assists, and character operation. Chapter two compares Sekiro, Monster Hunter: World, Hollow Knight, and other cases across rhythm, target learning, spatial action, and resource windows. Chapter three consolidates the findings for multiplayer action PVP and proposes state inheritance: a state created by one action can be read by the next action to change startup, range, movement, cost, or counter behavior.

## AI Collaboration

AI supported chapter structure, wording, consistency checks, tables, and formatting. I selected the cases, verified game rules, made the methodological judgments, and approved the final cuts. Uncertain source or mechanic claims are not treated as facts solely because an AI system suggested them.

## Outcomes

The public deliverable is a complete staged methodology document covering combat exchange, resource tradeoffs, advantage conversion, balance boundaries, long-term operation, and IP behavior translation. It can support later character prototyping, but it is not evidence that a specific IP character solution has already been completed and tested.

## Retrospective

The key editorial decision was to separate completed methodology from an unfinished character answer. The framework still needs prototype, numerical, and match testing. Until then, an accurate staged result is more useful than a seemingly complete character proposal.
